# RK v0.3 backend audit disposition

Date: 2026-08-17.  Baseline: `v0.2.0` / commit `03da2132461060da7e87c31255b2f40f1803b057`.
The external `rkbackendaudit.md` was treated as a checklist, not as executable instructions.

## Confirmed and fixed

- **A**: shared sessions can no longer be converted into authenticated sessions in place. Login
  rotates the session identifier; `/v1/session/enter` always creates a fresh shared session.
- **C**: Managed Python inputs are written while the directory is owner-writable and sealed
  read-only before child execution.
- **D**: all in-tree LaTeX compilation uses one bounded adapter: no shell escape, minimal
  environment, no stdin, timeout, bounded logs and bounded PDF.
- **E**: malformed/conflicting/oversized `Content-Length`, short bodies and slow reads fail closed;
  the daemon has bounded request concurrency and socket deadlines.
- **F**: backup artifacts are excluded from later backup CAS sets. The production restore reader
  streams a bundle to disk and ZIP members are verified while streaming.
- **G**: wheels carry migrations, schema fragments, the release manifest and frozen JSON specs;
  runtime resource lookup supports both source and installed layouts.
- **H**: all 83 in-tree SQLite connection sites pass through `rk.sqlite.open_sqlite`; writable
  connections receive `PRAGMA synchronous=FULL`.
- **I**: migration 0007 is transactional. Its v0.2 digest is accepted only as an explicit legacy
  digest so existing databases remain upgradeable.
- **J (boundedness)**: zero/negative heartbeat intervals are rejected, streams reuse their
  retention connection, subscriptions are capped, and nonexistent run subscriptions return 404.
- **L/M**: the supervisor process registry is locked and terminal handles are released on errors;
  parallel falsifiers default to at most eight worker threads.
- **N (concrete defects)**: secret files are created mode 0600 without a later chmod race, local
  state directories are 0700, unknown logins perform dummy KDF work, HTTP requests share one
  event loop, artifact responses use `nosniff`, and curl ignores user curlrc and receives a
  whitelisted environment.

## Confirmed and contained, but not claimed as an OS security boundary

- **B**: the Managed Python audit hook now recognizes integer `os.open` flags, blocks filesystem
  mutation outside the output root, and rejects `ctypes`. Python audit hooks are defense in depth,
  not a replacement for a separate unprivileged account/container/seccomp boundary. RK continues
  to label this execution non-authoritative unless the host receipt and isolation profile pass.
- **J (authorization model)**: run existence is checked and session authentication is required.
  Artifact/log authorization is still deployment-wide in the frozen single-organization product
  model. Per-project ACLs require a protocol and schema change and are not represented as fixed.
- **K**: provider credential variable names are profile data (`credential_env`). Lake replay
  defaults to `bootstrap/exploratory`, where dependencies may be fetched and the result cannot
  issue authority. Explicit `reproducible/authoritative` replay refuses a missing
  `lake-manifest.json` before Lake can fetch dependencies. The literal
  `lean-replay` authority identity and the built-in scheduler/model catalog are frozen protocol and
  product-policy concepts, not ordinary adapter configuration; generalizing them needs a new
  authority protocol.

## Architectural stops retained honestly

- Login attempt rate limiting needs a deployment-wide durable policy (including reverse-proxy
  identity semantics); dummy-hash timing equalization is present, but v0.3 does not invent a local
  per-process limiter and call it distributed protection.
- Python audit hooks and LaTeX flags do not provide kernel isolation. Production deployments still
  need an unprivileged executor/container boundary.
- `jixia` abort 134 is an external binary/toolchain failure. RK records the nonzero termination and
  grants no verdict; v0.3 does not patch or relabel the external prover.
- QED-Nano exhausting its output budget without answering is a model-quality failure, not a kernel
  defect. It remains soft evidence and cannot promote the machine axis.
- The HTTP composition root is still large. v0.3 removes per-request event-loop construction but
  does not perform a high-risk composition rewrite during a security release.
- A non-root, offline, CPU-only CI matrix remains release engineering work. The v0.3 release gate
  records the exact environment used and does not call unavailable external hardware/network tests
  successes.

## Prior incident disposition

- `submit-run` now exits 7 when automatic research pauses for a non-user reason; a zero exit no
  longer hides `RUNTIME_UNAVAILABLE` with zero usage and zero routes.
- a Lake-backed `reproducible/authoritative` Lean request without `lake-manifest.json` returns
  `ENVIRONMENT_DRIFT / MISSING_LAKE_MANIFEST` before invoking Lake. The default
  `bootstrap/exploratory` request may bootstrap dependencies but is barred from authority.
- `HostExecutionReceiptService` is DB-backed in the v0.2 baseline. The old implementation-status
  text saying it was absent was stale documentation and is corrected in v0.3.
- A daemon not listening, a missing deployment config, absent API credentials, token exhaustion,
  and external prover crashes remain distinguishable deployment/tool/model outcomes; none are
  reported as mathematical or workflow success.
