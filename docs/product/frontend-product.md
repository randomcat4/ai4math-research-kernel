# RK 数学研究工作台前端产品规格

状态：`FROZEN_TARGET / IMPLEMENTATION_REQUIRED`  
版本：`RK-FRONTEND-1.1`  
日期：2026-08-13  
适用项目：`C:\game\ai4math\magi\rk`

## 1. 产品边界与完成定义

本规格定义 RK 面向数学家、独立审查者和管理员的完整可视化产品。它不是静态仪表盘、CLI 外壳、
单题演示或 MVP。当前 RK 的真实入口仍是中文 CLI、JSON/Markdown 卷宗与 LaTeX/PDF；仓库中没有
本文所述完整图形前端、HTTP/SSE 产品接缝、动态 Worker 活动投影、文献工作台或受管科学计算工作区。
本文将这些缺失能力列为必须实现的产品后端，不把概念图或页面存在当作完成。

产品只面向单机或单组织部署，不扩展为多租户 SaaS。数学状态、事实、合同、权限、预算和终态仍由
`ResearchKernel` 治理；SQLite、CAS 与 execution ledger 按既有职责保存状态、不可变工件和执行回执。
前端缓存、搜索索引、图坐标、通知和活动投影全部可由权威状态重建，不得形成第二真值源。

只有同时满足以下条件才算完成：

- 三类用户都能从图形入口完成本文的全部真实旅程；
- 所有写操作进入同一内核命令 seam，页面不直写数据库或事实图；
- 动态任务、Worker、工具、Claim、验证、审查和论文共享同一 `run_id`；
- 断线、失败、撤销、合同修订和服务重启后能从权威 checkpoint 继续；
- 大规模事实和 Worker 历史仍可定位、阅读和操作；
- 全部场景验收使用当前树、真实进程和真实角色入口，不以 mock、fixture、截图或单元测试替代。

## 2. 不可违反的原则

1. **禁止防御性编程。** 只实现身份隔离、精确工件绑定、命令对账和恢复等产品正确性所必需的机制；
   不叠加重复签名、重复哈希、敌对容器或与真实威胁无关的安全工程。
2. **禁止 MVP 偷缩。** 页面、schema、adapter、假事件和测试通过均不等于产品可用。
3. **显示证据，不显示隐藏思维链。** 只显示公开任务、输入、工具调用、结构化结果、Claim、验证反馈
   和宿主决策，不采集或展示模型私有 chain-of-thought。
4. **不伪造进度。** 有可测分母才显示百分比，否则只显示状态、已耗时、最近活动和下一动作。
5. **工具成功不等于数学成立。** 进程退出、模型返回、Python 运行与 Claim 通过必须分栏显示。
6. **渐进披露。** 默认单路线、局部事实、单语义组展开；不把全部 DAG 和所有 Worker 同屏铺开。
7. **候选论文不出现在主页。** 候选 TeX 仅供独立整篇复核任务打开；严格终态链满足后才显示最终论文。
8. **成熟实现可复用。** Archon Horizon 的视觉与交互代码可在许可证、归属、接口和维护性审计后清理
   适配；不得让 Horizon 状态取代 RK 数学真值。

## 3. 用户、身份与正交状态

### 3.1 用户身份

- **数学家/Main：** 创建与修订合同、指导路线、暂停恢复、撤销事实、查看卷宗和最终交付；不能提交
  事实或代填审查结论。
- **Worker：** 在受管工作项中读取必要子图、调用获准工具并逐个提交原子 Claim；不能绕过验证写图。
- **Verifier/独立审查者：** 读取精确审查包并提交逐字段签名产物；不能修改研究或自行写事实。
- **管理员：** 部署、配置、诊断、预算和恢复；不因管理员身份获得数学晋级权。

当前后端已有窄 capability 和角色 guard，但缺少面向 UI 的身份会话、审查任务分派、当前身份投影和
登录/切换流程。必须新增这些产品能力，不能只靠隐藏按钮表达权限。

### 3.2 状态不得压成一个徽标

每个研究同时显示：

- `outcome`：`OPEN / PROVED / DISPROVED / UNRESOLVED`；
- `execution`：`QUEUED / RUNNING / PAUSED / WAITING / FAILED / CLOSED`；
- `closure_readiness`：开放义务、ClosureWitness、ROOT、整篇复核、编译各自状态；
- `blockers[]`：阻塞类型、影响范围、责任角色、发生时间和下一动作；
- `authority_summary`：当前最高数学权威及其证据来源。

“等待 Rethlas”不能覆盖另一条路线仍在运行；“工具调用成功”不能覆盖 Claim 被拒绝；`OPEN` run 不得
显示已完成。所有页面复用同一状态词典和非技术中文解释。

## 4. 全局信息架构

左侧固定八项导航：

1. 研究（“合同与材料”为研究内二级页）
2. 文献与新颖性
3. 路线与任务
4. 事实与谱系
5. 计算与工具
6. 人工与审查
7. 状态卷宗
8. 管理（仅管理员可见）

“候选论文”不在导航中。满足最终链后，“最终论文”作为状态卷宗中的终态条目出现。

顶栏持续显示研究编号、合同版本、修订号、当前身份、outcome、execution、未处理人工任务和连接状态。
全局搜索覆盖研究、合同、来源、路线、工作项、Claim、事实、审查、工件和错误；每条结果显示实体类型、
研究、合同版本、生命周期和权威，拒绝/撤销/过期内容不得与有效事实同样着色。

## 5. 核心工作台视觉与交互

### 5.1 固定布局

采用用户选定的第二张 Imagine 方向：

- 顶部为阶段、状态、阻塞和主要动作；
- 左中为 Archon Horizon 风格的章节/路线超节点与局部图；
- 右侧固定 Claim 检查器；
- 底部为按 `work_item_id` 聚合的执行抽屉，展开后显示 Worker 与 attempt；
- 不设置聊天主视图，不以模型头像数量表达研究进展。

### 5.2 路线超节点与单组展开

整个研究先按“数学里程碑 → 路线 → 拓扑带”折叠。`GraphGroup` kind 固定为
`ROUTE/MILESTONE/TOPOLOGY_BAND/BOUNDARY`；overview 显示路线/里程碑，局部 slice 才展开拓扑带。
默认只选择一条路线，并只展开一个组；展开新组时收起旧组，用户可锁定对比的两个 Claim，但不能同时展开多个大簇。超节点显示有效
事实数、待处理 Claim、开放义务、阻塞和最近活动，不用节点面积暗示数学重要性。

超节点不是第二套层级真值：里程碑来自研究规划，路线来自编排状态，拓扑带由确定性的查询规则生成。
有效事实图不按 lifecycle 分组，只有谱系视图可按 lifecycle 筛选。用户可保存视图偏好，但不能通过
拖动改变逻辑依赖。

### 5.3 有效事实图与 Claim 谱系严格分开

同一工作区提供两个明确标签页，不混画：

- **有效事实图：** 仅显示当前合同下 ACTIVE、验证通过、可晋级且可依赖的事实及有效边；
- **Claim 谱系：** 显示候选、待验证、拒绝、撤销、上游失效、superseded 与修订关系，且固定标注
  “这些记录不一定可依赖”。

默认是所选路线的局部有效事实图。页面固定显示：`局部 N / 总 M`、查询深度、路线、筛选、合同版本、
内核 revision 和最后事件游标。每个节点可解释“为何出现在这里”，并能显示到目标或 ROOT 的路径。
折叠簇使用混合状态图例，不能用整簇绿色暗示内部全部通过。

若当前路线依赖另一条路线，`cross_route_boundary` 以边界门显示外部事实、来源路线、方向、是否可依赖、
折叠数量及到目标路径；点击才切换路线。单路线显示不能让跨路线承重前驱消失，撤销/论文闭包绝不
使用显示筛选作为计算范围。

### 5.4 确定性图布局

图使用 Graphviz WASM 的确定性自上而下布局：相同节点、边、聚类和排序键必须产生相同坐标。服务端
返回稳定拓扑层和排序提示，前端用固定 Graphviz 版本生成坐标；布局版本写入可重建缓存键。换筛选或
展开组才重新布局，实时事件不随意打乱当前视口。用户缩放、选中和滚动位置本地保存。

Graphviz 只负责布局，不判断事实有效性。图必须有完全等价的列表/树表视图，供大图比较、键盘导航
和屏幕阅读器使用。

### 5.5 右侧 Claim 检查器

检查器按固定顺序呈现：

1. statement、Claim 类型、stable label、版本和合同版本；
2. 来源工作项/Worker、前驱和目标；
3. proof/evidence 正文与引用；
4. 六轴逐项状态及来源；
5. 验证门选择、实际回执、权威上限和拒绝修复建议；
6. 历史版本、撤销原因、替代 Claim 和影响闭包；
7. 可执行动作。

动作只能是当前身份与内核状态允许的动作。明显不可用项可隐藏，但最终判定仍由内核 guard 完成。

### 5.6 底部工作项与动态子智能体

底部按 `work_item_id` 聚合，不把每次模型重试画成一个新智能体。默认层级是：

`路线 → 里程碑/公开任务 → work item → worker run → attempt → 工具调用/Claim`。

只有编排器发出真实 `worker_run` 生命周期事件时才称为 Worker；否则称“工作项”。每项显示公开任务、
输入工件范围、当前动作、正在等谁、最近活动、已耗时、预算、工具、产出 Claim、失败和恢复次数。
历史完成项折叠计数并虚拟滚动；默认只展开活跃、失败和等待人工项。父子关系来自结构化派生事件，
不能从日志或语言模型文字猜测。详情不展示隐藏思维链。

当前后端缺少完整的 `worker_run / parent_worker_run / work_item / attempt` UI 活动投影及部分真实状态事件；
必须在编排器和工具运行状态转换处补结构化事件，不能由前端推断。

## 6. 页面规格、数据依赖与验收

### 6.1 研究列表与创建

产品行为：按 outcome、execution、阻塞、负责人、标签和最近活动筛选；从自然语言题目、期望范围和附件
创建研究；保存草稿；展示合同澄清前不可开始研究的原因。

附件必须显示上传进度、格式和大小、原件与提取文本、解析失败、数学符号差异以及页/段定位。刷新后草稿
和上传状态可恢复；解析不得静默改写公式。

后端依赖：研究摘要查询、创建草稿、ArtifactRef 上传、文本提取工件、合同草稿和正交状态投影。现有
内核有创建/工件基础，但缺少研究列表、草稿、上传会话和 UI 友好解析投影。

真实验收：从空数据目录上传一份含公式 PDF 和一份解析失败附件，完成草稿恢复、歧义处理、合同确认，
并从同一 run 进入研究；数据库或 CLI 不得人工补字段。

研究页增加“题池与科研谱系”二级视图，不新增一级导航：按冻结日期/学科查看 arXiv 开放题候选、版本、
撤稿、定义/量词/假设恢复、去重组、纳入/排除原因和完整分母；批量创建前必须人工确认题池快照和排除
规则。Zhao 显示“净室重新发现”与“导入证书核验”两个独立 run 模式和输入 manifest；`N2_AJT5` 历史
迁移项固定显示“候选，待当前验证门”，不能用旧项目颜色伪装成已验证事实。

### 6.2 合同与附件

逐项展示对象、定义域、量词、边界、精确否定、歧义、预算和版本。确认时冻结；修订前预览哪些路线、
checkpoint、队列、Claim、工具反馈、composition closed 和论文闭包失效，哪些 sibling 保留。旧 stable
label 新 hash 冲突必须用非技术中文解释。

后端依赖：合同读模型、修订影响查询和修订命令。现有合同能力可复用，但需要稳定 UI 投影与影响预览。

真实验收：真实研究运行中修订一个局部前提，旧 checkpoint 和受影响闭包失效、无关 sibling 保留；页面
刷新后影响结果不变，用户可从新 checkpoint 继续。

材料检查器必须并排显示原件页、提取文本、公式/图对象、解析器 build、页/段/公式锚点和差异。OCR 或
解析置信不足、公式字符变化和人工修订均是可见版本；修订生成新 extraction，不覆盖原件或旧锚点。
“文件已上传”“摘要相符”“UTF-8 可读”不得显示为“材料解析完成”。

### 6.3 文献与新颖性

页面包含检索问题、数据库/服务、endpoint、查询时间、来源版本、原始响应快照、原文位置、引用工件、
去重组、来源状态，以及来源
与合同、路线、Claim、BridgeSpec 的关系。对比表逐项展示已知结果、相邻结果、假设差异、结论差异和蕴含
方向。搜索无命中只能写“本次范围内未命中”，不得自动生成新颖性结论。

支持真实文献服务调用、手工导入、去重、原文定位、冲突来源标记、人工确认新颖性边界和引用导出。外部
服务故障时保留查询及失败回执，允许继续审阅已导入材料。

Matlas 结果卡只展示 `title/theorem/arxiv_id/theorem_id` 和“定理候选”身份；点击后由 arXiv connector
拉取精确版本原文与局部上下文，再进入假设/量词/符号/适用性核查。页面固定说明当前部署只有外部薄
客户端，没有 Matlas 服务端、语料、依赖图和向量 index。在线返回与历史快照重放使用不同徽标。

作者—论文—定理—引用搜索图是 RK 组合视图：每条边显示 Matlas/OpenAlex/Crossref/arXiv/人工导入来源，
不得把作者或引用边误标为 Matlas。搜索图只用于定位来源，不与有效事实图共用绿色权威语义。

后端依赖：当前缺少 Matlas 注册、OpenAlex/arXiv connector、SourceSnapshot、LiteratureGraph、
TheoremApplicability、CitationAnchor、PriorArtComparison、NoveltyReview 工作流及投影；现有 Crossref 与
Danus 薄客户端只能作为底层复用，文献工具回执不能冒充该工作流。

真实验收：在同一数学 run 中调用当前可用的 Matlas、Crossref、OpenAlex、arXiv，导入一份来源，合并
重复项，将一个定理与原文上下文关联到 Claim，记录假设差异并由独立人员确认边界；断开 Matlas 后从
原始响应重放，页面仍保留完整状态且不冒充在线或新颖性结论。

### 6.4 路线与任务

路线先以提议卡呈现目标、方法族、预期验证、里程碑、预算、依赖和终止条件。Main 通过一个正式
`ApplyRoutePlan` 动作批准/启动多条路线，并可暂停、停止、改优先级或预算；这不是自然语言 hint。
已启动泳道显示状态、终止理由和真实时间区间。并行只在实际区间重叠时显示，晋级按权威事件串行。

路线提议中单列“远域方法机会”：展示源问题规范化、候选目标域、领域距离、源域成熟度、目标域缺席度、
目标原生工具/verifier 优势、预期证书压缩、映射/假设损失、回译成本、最快死亡测试及来源证据。分数是
排序依据，不显示“更可能正确”。通过死亡测试后才能创建 BridgeSpec。

“消融”二级视图冻结题池、模型、工具 build、候选数、预算与终局 verifier，平行展示
direct/near/far-random/far-retrieval/full-RK 的全部任务、失败分母、成本和证书长度。页面不预设 full-RK
胜出，也不允许隐藏失败组。

后端依赖：路线投影已有基础；动态工作项、Worker 生命周期、父子派生和部分等待状态缺失。

真实验收：从至少三条结构不同提议中批准并启动，停止一条后它不再派生工作；另有两条路线真实时间
区间重叠、至少三个角色、一次工具失败和同 checkpoint 恢复；用户在 50 个活跃项和 500 个历史项中
三次交互内定位指定失败项、等待人工项和产出指定 Claim 的项。

### 6.5 事实图与谱系

支持 BM25、类型、生命周期、来源、验证方式、合同版本和时间筛选；支持前驱、后继、依赖闭包、反向影响
闭包、论文闭包和撤销 before/after 预览。Graphviz 局部图与等价列表共享选择、筛选和焦点。

后端依赖：BM25 与闭包算法已存在；缺少分页邻域、超节点聚类、总数、边界游标、稳定层级和服务器查询
seam。不能让网关每次搬运全 snapshot 后在浏览器重算。

真实验收：10,000 facts / 30,000 edges、几十层依赖下，从搜索进入单路线深度 2 图，展开一个语义组，
查看闭包和撤销预览；任何步骤不加载全图，返回数据明确 N/M，重复查询布局相同。该规模图只证明查询与
可读性，不冒充真实数学案例。

模型研究稿、OCR/Matlas/arXiv 抽取和历史项目迁移在 Claim 谱系中显示明确来源与“候选”状态。检查器显示
规范化器提出的原子边界、前驱、Claim 类型、未定义符号、自动 verifier plan、实际路由与返回；模型稿
不能直接成为有效节点。新事实被接受后，组合义务和 ClosureWitness readiness 的变化由内核事件显示，
不得用模型摘要代替。

### 6.6 计算与工具

能力目录只显示当前部署真实注册并通过诊断的 Lean、SMT、CAS、精确枚举、LeanSearch、jixia、受管
Python、本地证明模型和软 verifier。每次调用显示发起工作项、函数、结构化参数、attempt、运行状态、
墙钟、token、placement、stdout/stderr、文件、回执、恢复标记和数学权威上限。能力卡固定显示 provider、
model、build/version、profile、函数 schema、最近真实回执、usage、费用，并用“未配置/未探测/仅 smoke/
有产品回执/不可用/外部阻塞”区分证据等级。

当前基线须如实呈现：DeepSeek V4-Pro、DeepSeek Responses、LeanSearch、jixia、Lean、Z3、SymPy、精确
枚举和 DeepSeek-Prover 有可复用回执；GPT-5.6 未配置；Codex 纯文本通过但 shell 无真实副作用且 custom
apply_patch 执行失败；QED-Nano 仅简单 smoke；Rethlas 504；Archon 未有研究级调用。任何一项不能借邻项
成功变绿。

科学计算是完整工作区：脚本与输入工件编辑、环境和包清单、运行/取消、attempt 历史、流式日志、表格、
图片和文件结果、固定输入重跑、结果比较，以及从选中产物创建候选 Claim 或 checker 请求。探索性 Python
固定显示 `SOFT_TOOL_RESULT / NO_FACT_GRAPH_WRITE`；确定性 checker 走独立注册与证书路径。不给任意 shell。

后端依赖：Lean/SMT/CAS/枚举等有不同程度的运行接缝；当前缺少完整受管 Python profile、计算任务、
产物协议、取消/重跑/比较和 UI 工具健康目录。

真实验收：同一 run 由真实 Worker 调用 Lean、一个确定性工具和受管 Python；Python 使用 NumPy/SciPy/
SymPy/NetworkX 中已配置包生成表格与图片，失败一次后以同 checkpoint 修订恢复；结果只生成候选 Claim，
经统一验证后才进入有效事实图。

若远端调用处于“外部结果尚未确认”，工具卡提供四个受管动作：查询上游状态、导入可验证回执、明确
创建新 attempt 重跑、保持阻塞。任何导入仍须核对 binding 和 authority ceiling；系统不能自动重试。

### 6.7 人工提示与检查点

收件箱分为需要澄清、需要策略、需要审查和需要处理故障。数学家可在检查点提交换表示、停止路线、优先
引理或修改策略。每条提示绑定 run、contract、revision、checkpoint、目标范围和提交者，并具有
`QUEUED / APPLIED / REJECTED / SUPERSEDED / CANCELLED` 生命周期、编排器确认和影响摘要。生效前可撤回，
后续提示可明确替换；提示永不直接写事实图。

顶栏另有跨研究“待我处理”，只聚合需本人行动、长任务完成、预算临界和外部阻塞。每项来自后端
`ActionItemProjection`，含来源实体、责任身份、下一动作和创建 cursor；已读/确认只是界面偏好，不改变
数学状态。断线重连按 cursor 去重，不重复弹窗。

后端依赖：现有高层 hint 可复用，但缺少完整生命周期、目标范围、编排确认和 UI 投影。

真实验收：运行中提交“停止路线 A、优先路线 B 的引理 L”，看到提示排队、在安全 checkpoint 生效、
路线行为实际变化；再验证生效前撤回及旧 revision 提交时的差异提示。

### 6.8 独立审查工作区

任务包含 assignee、作者主体、独立性结果、合同/修订/Claim/ROOT/闭包/精确 TeX 摘要绑定、领取、过期、
重分派和完成状态。审查者在一个界面查看必要依赖闭包、证明、证据、工具回执、引用和 TeX/PDF，并把
意见锚定到 Claim 或 TeX 行号。

组合审查显式填写 `proof_checked`、`scope_checked` 和六部分结论；不预填 true。任一缺失或 false、身份
不独立、摘要不匹配、过期合同、UNMANAGED 或 `authority_effect=NONE` 均不可晋级。意见只能接受、拒绝或
要求修订并返回原任务，不能直接写事实图。

ReviewTask 只保存分派、binding、独立性和签名工件引用；草稿 true 值不是晋级输入。签名动作由当前
窄审查者身份完成，Main/Gateway 没有构造签名工件的入口。

后端依赖：现有签名 artifact、guard 和论文复核基础可复用；UI 身份会话、任务分派、锚定评论、领取/
重分派和过期投影缺失。

真实验收：两名窄身份分别完成组合与整篇复核；逐项验证 false、缺失、错误摘要、作者身份和过期工件
均被运行时拒绝；主界面无法代填，反馈回到原 Claim/论文任务。

### 6.9 状态卷宗与最终论文

卷宗在任何状态都可看，包含题目、合同、来源、路线、事实、失败、撤销、计算、审查、人工提示、预算、
限制和开放义务。未闭合时名称是“研究卷宗”，显示 OPEN/UNRESOLVED/BLOCKED，不显示论文卡片。

角色可见性固定：数学家/Main 在研究列表、路线页和卷宗只看到“数学结论已冻结，等待独立整篇复核”，
没有候选 TeX 链接、缩略图或论文卡；`CANDIDATE_TEX` 只是技术状态。只有分配给 PAPER_REVIEWER 的
精确 ReviewTask 返回候选 TeX。

只有以下精确链全部满足才出现“最终论文”：有效 ClosureWitness → 唯一 ROOT terminal → 与当前合同和
kernel revision 一致 → Finalize 后 run 非 OPEN 且有 `final_outcome` → 从 finalized snapshot 的冻结 ROOT
闭包生成候选 TeX → 独立整篇复核绑定精确 TeX/ROOT/闭包 → 同一精确 TeX 编译 PDF 成功。任意 LEMMA、
多 ROOT、复核后 TeX 变化或编译失败均不可显示。Finalize 后普通数学命令关闭；仅三种窄 publication
命令可以生成候选、提交复核和编译，且不能反向修改数学状态。

编译失败进入排版修复任务。任何 TeX 修改生成新工件版本；若精确摘要变化，整篇复核必须按规则重新执行，
不能由 UI 声称“只是排版”。

后端依赖：现有论文主链和工件基础可复用；缺少完整前端工件流、编译返修任务和版本比较投影。

真实验收：同一当前树 run 完成受管审查、ClosureWitness、唯一 ROOT、Finalize、候选 TeX、独立整篇
复核和 PDF；
另运行一次编译失败—修复—新摘要复核闭环。主页全过程无候选论文预览。

### 6.10 管理员中心

管理员可从干净机器初始化数据目录与 Main/Worker/Verifier 窄身份，配置模型、文献服务、Lean/Mathlib、
jixia、SMT/CAS、枚举、Python、TeX 和硬件计划；运行真实最小诊断并查看版本、最近成功/失败、外部阻塞、
placement、并发、token、墙钟、费用和 `UNKNOWN_COST`。

支持启动/停止、升级、schema migration、SQLite+CAS 备份、恢复到新目录、重建可派生投影/索引、查看
checkpoint/队列/未消费回执、恢复或取消工作，并导出不含凭据的诊断包。Rethlas 504 显示外部阻塞并允许
人工重试，不进行无休止后台重试。

后端依赖：配置、预算、调度和运行账已有部分基础；缺少完整管理查询、诊断、安装升级、备份恢复、投影
重建和诊断包产品能力。

真实验收：干净主机安装初始化，配置可用工具，分别复现缺包、外部 504、GPU 不可见、TeX 缺失，完成
当前版到下一版升级、备份、恢复到新目录并继续原 run；不手改数据库。

管理员另可配置文献 connector、OCR/解析 profile、arXiv 抓取策略和外部专家/作者确认通道。Matlas 页面
必须清楚显示“外部托管薄客户端”及端点状态，不能出现本地语料/index 容量；GPT-5.6、Rethlas 等未配置或
阻塞能力保留下一动作和最后回执。批量题池的抓取量、入选数、排除数、失败数和待确认数始终同屏。

## 7. 写命令、断线与陈旧页面

读侧使用 snapshot + 单调 activity cursor；在线更新使用单向 SSE，断线后从游标补齐。全库 cursor 对
单 run 可自然跳号；正常跳号或暂无事件不是空洞，只有服务明确 `CURSOR_EXPIRED/CURSOR_UNAVAILABLE`
才取新原子 snapshot。运行事件可引用较早 research revision，前端只按 cursor/event_id 排序，不据此丢弃。

写侧每次用户动作生成稳定 `request_id`，后端返回可查询 `ProductReceipt`，状态只有
`PENDING / DECIDED / OUTCOME_UNKNOWN`。断线后先按 request_id 对账；PENDING 不显示完成，DECIDED
只读取不可变 kernel receipt，OUTCOME_UNKNOWN 不自动重试。Claim、合同修订、撤销、工具、审查和
Finalize 都遵循该语义，不增加第二操作 ID 或第二幂等账。

若页面 revision 已旧，后端返回当前 revision、状态差异和可重新应用的草稿；前端不得笼统报错或静默覆盖。
同 stable label 不同 hash、旧 checkpoint、已撤销前驱和过期审查分别给出“发生了什么、数学影响、谁能处理、
下一动作”。当前后端缺少通用 ProductReceipt 查询和部分幂等对账能力，必须实现。

## 8. 后端产品 seam

前端只面对一个深的 `ResearchProduct` 模块，不为每个页面各造旁路：

```text
桌面壳 / 浏览器
      │ typed query + command + SSE + artifact stream
      ▼
ResearchProduct
  ├─ query(QuerySpec) -> ProjectionPage
  ├─ command(CommandEnvelope) -> ProductReceipt
  ├─ subscribe(run_id, after_cursor) -> EventStream
  └─ artifact(ArtifactRequest) -> Stream
      │
      ▼
ResearchKernel + orchestrator + fact graph + execution ledger + CAS
```

`QuerySpec` 统一覆盖研究列表/摘要、合同/材料影响、材料提取、文献/新颖性/多源搜索图、批量题池、
路线计划/远域机会/消融/工作项、科研谱系、事实邻域/搜索、Claim、计算/工具、提示/审查、待我处理、
ProductReceipt/Job、卷宗/发布和部署/备份。复杂查询下沉到产品读
模块，调用者和真实验收走同一 interface；Gateway 不直接读写 SQLite，不复制权限或终态判断。

创建研究和管理员状态改变也是 `command` 的带类型请求；研究列表和部署健康也是 `query` 的带类型请求。
不得因页面增多而扩展新的顶层接口。

所有投影携带 schema_version/stable_entity_id；RUN 投影另带
run_id/research_revision/contract_version/last_cursor；GLOBAL/DEPLOYMENT 投影带 deployment_id 与相应
deployment/catalog fence，列表项各带自己的 run context。搜索索引、Graphviz 坐标、通知与活动视图
均可从 snapshot、事件账和工件重建。

必须新增的后端能力至少包括：

- 研究列表、正交状态和 blocker 投影；
- UI 身份会话、审查分派和窄 capability 绑定；
- 材料 OCR/解析、数学公式差异与页段/公式锚点；
- Matlas/OpenAlex/Crossref/arXiv connector、查询快照、多源文献图、适用性和新颖性工作流；
- 批量 arXiv 题池、版本/撤稿、完整分母和专家/作者确认待办；
- 研究稿原子化/verifier plan、远域机会/消融与科研谱系；
- worker/work_item/attempt 结构化活动事件；
- 分页事实邻域、超节点聚类、总数和稳定拓扑提示；
- 受管 Python 计算任务与产物协议；
- 人工提示完整生命周期；
- ProductReceipt 与断连对账；
- 工件分段/流式查看、上传和版本比较；
- 管理诊断、备份恢复、投影重建和诊断包。

## 9. 非技术中文与可访问性

界面默认中文，不把 `promotion_eligible`、cursor、digest、checkpoint 等内部词直接扔给用户。每个状态用
“发生了什么 / 对数学结论有什么影响 / 谁能处理 / 下一步”四句以内解释，并保留“查看技术详情”。

核心文案与术语约定：

- Claim：候选阶段称“待核验命题”，进入历史后称“命题记录”；Fact：“已验证事实”；
- Worker：“研究执行任务”；work item：“研究任务”；worker run：“一次执行”；attempt：“第 N 次运行”；
- ROOT：“最终结论”；ClosureWitness：“闭合检查记录”；revision：“研究修订号”；
- contract version：“题目合同版本”；blocker：“待处理事项”；OUTCOME_UNKNOWN：“外部结果尚未确认”；
- BridgeSpec、stable label、digest 仅出现在“技术详情”；

- `TOOL_CALL_SUCCEEDED`：工具调用完成，不写“证明成功”；
- `VALIDATION_ACCEPTED`：验证通过，可按所示权威依赖；
- `SOFT_CANDIDATE_ONLY`：仅供参考，不能作为已证事实；
- `WAITING_REVIEW`：等待独立审查者填写，作者不能代填；
- `BLOCKED_EXTERNAL`：外部服务暂不可用，已完成部分仍保留；
- `UNRESOLVED`：在当前合同和预算下尚未闭合，不写“失败”。

可访问性必须包含：全键盘操作、可见焦点、200% 缩放、非颜色形状与文字状态、高对比、减少动画、图的
等价列表、公式可读替代文本和复制 LaTeX、实时事件节流、更新后焦点不跳走。窄屏保留查看、搜索、指导、
审查和恢复，不承诺手机编辑大图。

真实验收由仅键盘用户与屏幕阅读器走完：创建合同、定位局部事实、查看权威、提交人工提示、填写审查和
下载最终 PDF；不得仅用自动扫描器判定通过。

## 10. 性能与诚实体验指标

- 本地已有研究 p95 2 秒内出现摘要，图、日志和工件后加载；
- 权威事件落账后 1 秒内出现在在线前端；
- 支持至少 500 个历史 Worker、50 个非终态项的过滤和虚拟滚动；
- 10,000 facts / 30,000 edges 下，默认局部图不超过 200 节点，查询 p95 500ms；
- 200 节点 Graphviz WASM 布局 1 秒内可交互，相同输入布局稳定；
- BM25 p95 500ms，并报告总数、返回数和截断；
- 10MB 日志与大型 TeX/PDF 分段或流式读取，不冻结页面；
- 页面、应用和服务重启后恢复研究、选中实体、视口及未确认人工任务；
- 无可测分母的工作永不显示虚构百分比。

## 12. 实施顺序与发布口径

实施按承重依赖推进，但任何批次都不是可停止的 MVP：

1. `ResearchProduct` 深模块、身份会话、查询/命令/事件/工件 interface 与断线对账；
2. 正交状态、工作项/Worker/attempt、材料、文献、题池、审查和人工提示投影；
3. 研究、合同、总览、路线和第二张 Imagine 核心工作台；
4. 分页事实查询、超节点、Graphviz WASM、列表等价视图；
5. Matlas/多源文献图、研究稿闭环、远域消融、批量题池、计算工具与人工审查；
6. 卷宗、严格最终论文链、编译返修；
7. 管理员生命周期、可访问性、规模和 F01–F21 全链验收；
8. 许可证归属、用户/管理员手册、安装包和实现状态。

在 F01–F21 全部通过前，只能发布为“可视化产品开发中”。不得写“动态 Worker 已支持”“实时 DAG 已
完成”或“完整数学研究工作台”。Rethlas 等外部能力只在当前部署真实健康并取得当前 run 回执时显示可用；
上游 504 时诚实显示外部阻塞，不影响其他可用能力继续工作。

## 13. 明确非目标

- 多租户 SaaS、组织计费、分布式数据库或第二消息总线；
- 重写 Lean、LeanSearch、jixia、Rethlas、Archon 或基础模型；
- 展示或保存隐藏思维链；
- 给 Worker 任意系统 shell；
- 用漂亮图、模型置信度、多数票或工具退出码替代数学验证；
- 在主页或普通导航中显示候选论文预览；
- 自动宣称新颖性、期刊等级或问题已经解决。
