## 1. 失败诊断：六个结构性根因

审计列了 13 页症状。症状不能直接当需求，否则得到 13 个补丁而不是一个能用的产品。

**R1 · 界面是内核对象模型的投影，不是用户任务的投影。**
八项导航精确对应八个后端模块，页面渲染"某类对象的列表"。对象为空，主体就变成
`EMPTY · 当前范围内尚无此类真实对象`（05、09、13）。对象为空是后端事实，
但"我现在该干什么"从来不是空的。

**R2 · 没有单一状态真值，每页各自推断。**
顶栏 `RUNNING`、合同页"尚未创建研究"、路线页 `EMPTY / 0 of 3`、卷宗页"结论已冻结"。
用户读到的不是"复杂状态"，是"这个系统不知道自己在干什么"。
**逐组件的诚实之和，是全局的不诚实。**

**R3 · "不伪造"被写成了文案，而不是被设计成了结构。**
免责声明占据的面积超过工作本身。更严重的一类是**静态文案冒充状态**：
11 卷宗页那句"结论已冻结，等待独立复核"不绑定任何字段，与"卷宗当前不可用"并列。

**R4 · 交互原语是"打 ID"，不是"选对象"。**
表单结构 = 命令信封结构。首次用户不知道 ID 从哪来，因为产品没有提供"从哪来"这条路径。

**R5 · 杂志排版被套用在了操作台上。**
56px 大标题 190px + 常驻调试条 + 常驻底部抽屉，首个可点击业务控件在 y≈580 以下。
同时 `PAUSE RESEARCH` 占据唯一强主按钮位——**把"我能对你做的唯一事"当成了"你该做的下一件事"。**

**R6 · 没有可机器判定的门禁，所以编码故障也能上线。**
12 管理页整片中文渲染成 `????`。一次自动截图加一条正则就能拦住。

**R3′ · R3 的最高层复发（五轮攻防后新增）。**
整个界面的存在本身，是一段没有绑定字段、也没有人署名的断言：
它让用户以为"产品所知道的 = 这项研究"。见 A9。

## 2. 设计公理

九条。每条尽量可判定；**判定方式覆盖不到的部分，必须在条款里写明它覆盖不到什么。**

| # | 公理 | 判定方式 |
|---|---|---|
| A1 | **单一投影者，而非单一真值。** `StageProjection` 是**被录入状态**的唯一投影者；任何页面不得自行推断阶段。**它不是这项研究状态的真值。** | 代码检查：唯一生产者 |
| A2 | **每一句状态断言，要么绑一个字段，要么绑一个人。** 机器状态 → `data-state-binding`；人类判断 → `data-attributed-to`。两者都没有 → 不允许存在。 | 构建期 lint + arity lint（§2.1） |
| A3 | **互斥状态不得同屏。** 唯一豁免：`StateConflictBanner` 内部允许并列矛盾读数并各自标注来源。 | 渲染期断言 + E2E 全页扫描 |
| A4 | **首屏必须准确表达当前状态，而不是必须提供动作。** 仅当 `kind ∈ {ACT, CHOOSE}` 时必须有 enabled 主控件；`kind ∈ {WAIT, BLOCKED, NO_SUGGESTION, NOT_COMPUTED}` 时 `NextActionCard` 内**必须没有** enabled 控件。 | G4：断言**假动作的缺席** |
| A5 | **产品内部对象的标识符必须可达。** 主流程不得依赖手输**内部**标识符。**外部**标识符是合法且必要的，必须用 `ExternalIdentifierField` 显式标注并给出获取指引。 | G5：流程完成性测试 |
| A6 | **每个空与错都有出路**，除 `OPEN_UNDECIDED` 外。 | 类型必填 |
| A7 | **诚实是结构，不是段落。** 可信边界用徽标、分栏、权威上限表达；单区域可见 `TrustNote` ≤ 1。 | E2E 计数 |
| A8 | **禁止异质合并。** 任何展示给用户的计数、布尔、等级或颜色，其构成成分必须同质（全机器可判定，或全人类断言）。异质量必须分栏或分通道，不得合并。 | 见 §18.1：**本公理的实现依赖后端，2.1 无法独立交付** |
| A9 | **产品必须表达自己的无知边界。** 见 §2.2。 | 部分可判定；其局限见 §2.2 |

### 2.1 A2 的判定能力与其边界

`data-state-binding` 只能证明**有绑定**，不能证明**绑对了**。三重加固：

1. **允许集**：`lexicon.json` 每个文案 code 附带允许的 binding 集合，lint 校验 `binding ∈ 允许集`
2. **arity lint**：**终态类文案的允许集大小必须 = 1**。把"复核已通过"绑到 `closure_readiness.compile` 会构建失败——不是因为 lint 懂语义，是因为它数了个数
3. **全枚举变异（G13）**：变异体**自动生成**为"绑到 projection 的每一个其他字段"，不由实现者书写，因此不与允许集覆盖同一块空间

**明确的局限：**`lexicon.json` 里"某文案允许绑某字段"这条记录，本质是一句自然语言的语义规定，
**靠人评审保证正确**。它是集中的、可审的，但它不是类型层面的消除。因此 `lexicon.json`
必须由**数学侧署名**（署名与日期写进文件），并在**第 1 批**交付（§17）。

### 2.2 A9 的形式与它测不到的东西

**文案必须是开放式的，不得逐字列举**：

> 「本产品记录的是这项研究**被录入**的部分。任何未被录入的东西——纸面推导、口头讨论、
> 本地未导入的实验、放弃的尝试，**以及任何其他未录入的东西**——不在其中。」

一个逐字列举四类的边界声明会被读成**完备**的边界声明，那是一份虚假的无知清单。

**可绑定的量：**补录事件带两个时间戳（真实发生时间 / 事后录入时间），其**差值分布**
是产品已知盲区的测量，显示在部署面板与卷宗上。

**它测不到的东西（必须与该指标同屏）：**补录时延只测量"我知道我曾经不知道"。
永远不补录的内容，这个指标永远看不见。**因此这个指标最好看的时候，可能正是产品最盲的时候。**

## 3. 状态模型

### 3.1 `StageProjection` 契约

```
StageProjection {
  schema_version, deployment_id
  run_id?, research_revision?, contract_version?, last_cursor

  stage_focus         由**用户**设定，不由服务端推断；默认落在最近有事件的阶段
  stages: [ { code, status, preserved?, note? } ]     # 可多个同时 CURRENT
     status: DONE | CURRENT | LOCKED | SKIPPED | INVALIDATED | REDOING
     # 无 index/total，无分母，无百分比

  outcome:  OPEN | PROVED | PROVED_CONDITIONAL | DISPROVED | UNRESOLVED
  execution: QUEUED | RUNNING | PAUSED | WAITING | FAILED | CLOSED
  closure_readiness: { obligations_open, accepted_hypotheses[], closure_witness,
                       root, whole_review, compile }
  authority_summary: { level, source }

  next_action: {
    kind: ACT | CHOOSE | WAIT | BLOCKED | NO_SUGGESTION | NOT_COMPUTED | DONE
    title, why, target_page, target_anchor, command?, required_role
    disabled_reason?    # kind != ACT 时必填
    waiting_on?         # 仅当等待对象是**外部**对象时；等待自己的判断不是 WAIT
    considered[]?       # kind == NO_SUGGESTION 时必填：{候选动作, 为何排除, 证据引用}
    scope?              # kind == NO_SUGGESTION 时必填：服务端实际查了哪些
  }

  blockers[]:  { kind, scope, owner_role, since, recovery_action, target }
  capability_availability: { <page_key>: PUBLISHED | NOT_PUBLISHED | DEGRADED | FORBIDDEN }
  researcher_beliefs[]:  # 见 §3.5
}
```

**`ImpactProjection` 与 `StageProjection` 分离。**闭包计算（`INVALIDATED`、`preserved`、
撤销影响）不进 `StageProjection`——后者是廉价的、cursor 驱动的、不做图遍历的、300ms 内返回的。
阶段条在闭包算完前显示**「影响计算中」**，不显示数字，**也不显示缓存的旧数字**。

### 3.2 阶段：具名芯片，无序号

```
S1 立题与合同 · S2 材料与文献 · S3 路线规划 · S4 执行与取证
S5 验证与晋级 · S6 闭合检查 · S7 独立复核与交付
```

七步是**用户心智模型**，不是内核 FSM，且**不得作为可操作性的判据**（见 §3.4）。
研究是并发与可回溯的：多个阶段可同时 `CURRENT`；S6 的发现驱动 S1 重做时，
S1 亮 `REDOING`、S6 转 `INVALIDATED` 并标注"由 S6 的发现触发"——**因果方向朝上**。

**`index/total` 与"第 N 步 / 共 7 步"整条删除。**一个会从 6 掉回 1 的数字，
无论文案怎么写，都会被读成"我刚才十一天白干了"。

`REDOING` 携带 `preserved`，但按 A8 **分栏，不求和**：

```
preserved: { machine_decidable: 26, human_asserted: 8, soft_only: 6 }
```

**永远不显示"32"。**放不进 72px 芯片就不放：芯片只显示 `REDOING · 影响待复核 →`，
分栏数字在影响页。

**默认翻转：**合同修订时，**人类断言的依赖关系默认不计为保留**，进"待你确认（8）"；
只有机器可判的 26 条自动保留。一个把人类断言算进"已保留"的数字，唯一作用是让人跳过检查。

### 3.3 三条界面规则

**规则 1 · 冲突的解释权。**
- 页面 cursor < 服务端 cursor → 页面确实旧 → 重新读取
- **cursor 相同但内容冲突 → 系统缺陷，不是用户的问题。**横幅写"系统内部状态不一致，
  已记录（编号 X）"，两种读数**并列显示并各自标注来源查询**，提供导出诊断
- **人与投影冲突 → 见 §3.5。默认解释是"投影缺少了人所知道的东西"，不是"页面落后了"**

**规则 2 · 不可用 ≠ 无数据 ≠ 终态。**三者由 `capability_availability` 与数据长度共同判定，
渲染三种**不同组件**，绝不复用同一个空容器。见 §6.1。

**规则 3 · 下一动作阶梯。**服务端按固定优先级选出，**控制类动作永不进入该槽位**：

```
1 解除阻塞 → 2 推进研究 → 3 做出选择 → 4 等待外部 → 5 已完成
无法定位到以上任何一项时：NO_SUGGESTION（必须说明查了什么、排除了什么）
未作判断时：NOT_COMPUTED
```

`PAUSE / STOP / 改预算 / 刷新投影` 属于**研究控制**与**诊断**，进顶栏菜单与页面工具条。

**`NO_SUGGESTION` 与 `NOT_COMPUTED` 必须分开，因为这两句话对数学家的价值差一个数量级：**
- `NO_SUGGESTION`：「已检查〈scope〉，没有可推荐的下一步。已排除：…」——这是一个合作者的判断
- `NOT_COMPUTED`：「系统未对此作判断。」——这是沉默

**`NOT_COMPUTED` 是可门禁的**：G4 断言主流程页面的发布构建中不出现它。
脱离它的出路是"去算，然后说 `NO_SUGGESTION`"，**不是"编一个 ACT"**——逃逸口堵在自己那一侧。

### 3.4 阶段不得决定可操作性

> **可操作性只由服务端 guard 的真实返回决定；阶段只用于解释。**

`LOCKED_BY_STAGE` 的判据是**该命令的 guard 实际拒绝**，不是"stage 未到"。
guard 不拒绝就不许显示 Locked。**一个能决定按钮是否可点的东西就是 FSM，
不管文档里叫它什么。**

直接后果：
- 写下一条命题**不需要**先有路线（草稿命题随时可记，标 `SOFT_CANDIDATE_ONLY`，不进事实图）
- **05 计算与工具页永不 LOCKED。**无研究、无合同也能跑受管 Python：1.1 §6.6 已规定
  探索性计算是 `SOFT_TOOL_RESULT / NO_FACT_GRAPH_WRITE`——**既然不写事实图，
  就没有任何理由要求先冻结合同。**一个猜想有六成概率在 30 秒枚举里当场死掉，
  产品不许挡在那 30 秒前面

### 3.5 `ResearcherBelief`：人报告自己的状态

**这项研究状态的主要部分住在研究者的脑子里。服务端持有的是一个滞后的、低维的投影。**

第 12 天下午，研究者知道路线 A 死了，说不出为什么——没有反例、没有失败运行、
没有 blocker、没有一条 `EvidenceComposition` 变红。产品按它能看到的一切每天都是对的，
按这项研究的真实状态每天都是错的。而那两周里，这项研究最重要的事实就是
"主研究者不再相信路线 A"。

`AttributedJudgment` 的一个变体，**用于人报告自己的状态，而不是评判某个对象**：

```
ResearcherBelief {
  by, at
  about          指向路线 / Claim / 分解 / 整个研究
  statement      自然语言，允许"我说不出为什么"
  confidence_direction  信任 | 不信任 | 动摇
}
```

- 不进事实图，不影响 `publishable.machine`，不参与任何机器判定
- **但它改变显示**：被研究者标注为"不信任"的路线，不得再作为自信的 `next_action` 出现；
  `NextActionCard` 必须显示"你在〈日期〉标注过不信任这条路线"
- **随时可写，不需要做出决定。**`DecisionRecord`（§4.4）只在放弃的那一刻存在，
  而研究的那两周全部发生在决定之前

**`StageBar` 与研究者读数并列。**既然投影不是真值，它就不能独占那 72px：
阶段条右侧固定一格「我的读数」，显示最近的 `ResearcherBelief` 与写入入口。
屏幕上同时呈现两种读数，各自标注来源，**都不宣称自己是真的**。

§16 的非目标「不用置信度替代数学验证」仍然成立——**那条禁止的是把置信度
喂给数学判定，不是禁止界面里有人表达自己的信念。**

### 4.1 导航

```
01 研究        ├ 概览（默认）├ 合同与材料
02 文献与新颖性 ├ 检索 ├ 来源库 ├ 新颖性审查
03 路线与任务   ├ 路线 ├ 执行现场
04 事实与谱系   ├ 有效事实图 ├ Claim 谱系 ├ 撤销闭包
05 计算与工具   ├ 工具目录 ├ 运行 ├ 产物
06 人工与审查   ├ 待我处理 ├ 我的审查任务 ├ 身份
07 状态卷宗     ├ 研究卷宗 ├ 最终交付（终态链满足才出现）
08 管理         └ 部署与健康（只读）
```

二级页用标签页，不用新页面。`NOT_PUBLISHED` 的导航项**不隐藏**，带灰色"未提供"角标——
隐藏会让用户以为产品没有这个概念，角标让用户知道边界在哪。

**已从前端范围删除**（理由见 §18.3）：消融视图、远域机会视图、题池与科研谱系、
管理中心的图形化备份/恢复/升级/迁移。

**删除的元素：**56px 研究大标题（降为顶栏单行）；常驻"活动链实时 cursor N"条
（cursor 是调试量，降为顶栏 `ConnectionChip`）；"心跳不计作业事件"常驻说明；
每页重复的 `CURRENT EVIDENCE ROUND` 全大写标签。

### 4.3 回归者简报

"距上次会话 > N 天"是机械可判的。满足时，首屏**不显示常规的下一步**，显示**「你不在的时候」**：
发生了什么、什么被放弃了**及其理由**、什么被撤销了、哪些人类断言过期了、
「最薄的环」在这段时间里的变化。

**首屏最贵的位置，对回归者服务的是过去。**成品定理可以重建，
失败的尝试和放弃的理由不可重建；产品对后者的保存责任高于对前者。

### 4.4 `ThinnestLinkPanel`（最薄的环）

与 `NextActionCard` 同一行、同一层级、常驻每一页，280px。

**它不排序。**把不可通约的信号全序化正是 A8 禁止的事，而"最值得怀疑的三条"
必然要求全序化（注意力是标量）。因此面板呈现**互不比较的单信号极值**，每条一行：

```
人类断言最多   C-17 · 4 处，最早 21 天前
最久未复核     C-3  · 合同修订后 12 天未核
改动最多       C-61 · 7 版，3 天
```

- 每条都是**单一信号上的极值**，良定义，**不需要跨信号通约**
- 每个信号贡献恰好**一行 = 一个对象**，装得下 280px，不退化成跳转链接
- **显示哪三个信号由用户选择并可固定**——"哪个维度值得看"这个判断因此**绑到人**，
  而不是由一个没有署名的权重函数决定

**两族信号（缺一不可）：**
- **证据脆弱性**：`AttributedJudgment` 数量与年龄、SOFT 支撑、外部依赖深度、
  合同修订后未重新核对、忠实性变异挑战已测覆盖最低
- **投入**：修订版本数、失败 attempt 数、累计耗时、被重写次数、路线重来次数

> 只有证据脆弱性一族是不够的：一条被改了七版、花了三天、是整个证明技术核心的引理，
> 在证据脆弱性上全绿。**错误集中在难的地方，而难度只在投入信号里可见。**

**理由必须结构可判定，产品永远不说"这条可能是错的"**，只说
"这条的证据构成最依赖人的断言（4 处，最早 21 天前），且合同修订后未重新核对"。

**面板是双向的。**「我认为最薄的是 C-61，因为我改了七版」生成一条 `AttributedJudgment`，
**持久化并置顶显示给下一个人**（包括三个月后的自己和接手的博士生）。
一个只输出不接收的面板，是一个不听人说话的复核者。

## 5. 交互模型：对象优先

### 5.1 按风险分级的动作骨架

| 风险 | 骨架 | 适用 |
|---|---|---|
| 高 | 选对象 → `ImpactPreview`（服务端计算，不可跳过）→ 确认 → 回执 | 撤销、合同修订、Finalize、身份切换 |
| 常规 | 选对象 → 提交 → 回执 | 提交待核验命题、发起运行、导入来源 |

**专家通道（与首次用户路径同等一等）：**命令面板（Ctrl+K，动作名与对象搜索同框）、
多选批量、"沿用上次参数"、键盘序列全覆盖。

### 5.2 标识符的位置

- **内部标识符**：输出可见（检查器"技术标识"分组，带复制）；**主路径不依赖手输**；
  URL 深链 `?claim=<id>` 合法；**搜索框接受任意串**（自然语言 / 稳定标签 / digest 前缀 / 完整 ID）
  并明写它接受什么——**往搜索框粘贴已知标识符是定位，不是"打 ID"**
- **外部标识符**（`slurm-8814023.abc`、mathlib 声明名、上游快照 ID）：
  `ExternalIdentifierField`，必填来源系统名、一句"本产品无法为你提供它"、
  **以及去哪里找的具体指引**（作业回执邮件 / `squeue -j` / 上游控制台路径）

> A5 的失效区（产品与外部世界的边界）与产品最引以为豪的诚实性区域是同一块。
> 承认这一点，并在边界上帮用户，好过假装边界不存在。

### 5.3 禁用与高风险

禁用按钮必须就近说明缺什么：`disabled` 与 `disabledReason` 同时存在，
`disabledReason` 是"缺少 X"或"需要 Y 角色"的具体句子，带跳转。

身份切换是四步向导（角色权限对照 → 凭据来源 → 未保存草稿逐项处理 → 输入凭据），
不是一个下拉框。

## 6. 空态、错误与不可用的分类学

**`EMPTY` 这个词在产品中被彻底删除。**

### 6.1 七类

| 代码 | 判据 | 主文案骨架 | 恢复路径 |
|---|---|---|---|
| `NOT_STARTED` | 已发布、无数据、guard 不拒绝 | "还没有〈对象〉。" | 创建主动作 |
| `LOCKED_BY_STAGE` | **guard 实际拒绝** | "〈对象〉将在〈条件〉后出现。" | 具名链接 |
| `NOT_PUBLISHED` | `capability_availability` | "本部署尚未提供〈能力〉。研究本身没有问题。" | 管理页 + 联系管理员 |
| `FORBIDDEN_ROLE` | guard 角色拒绝 | "〈角色〉才能查看。你当前是〈角色〉。" | 身份说明 |
| `BLOCKED_EXTERNAL` | 上游不可用 | "〈服务〉暂时不可用。已完成的部分全部保留。" | 保留内容入口 + **人工**重试 |
| `TRULY_EMPTY` | 已发布、guard 允许、0 条 | "当前范围内没有〈对象〉。" | 放宽范围 |
| `OPEN_UNDECIDED` | **内容由用户自己创作的容器**（笔记、草稿、沙盒） | "这里现在是空的。" | **无，A6 对此类豁免** |

`OPEN_UNDECIDED` 的合法位置由组件注册表声明（有限枚举），不是一个免除一切义务的通用出口。
**数学研究的第一原理是想法先于结构；一个允许你还没想好的房间，好过一扇只通往一个房间的门。**

### 6.2 错误四段式

```
发生了什么       一句话，中文，不含错误码
对数学结论的影响   明确写"不影响已验证事实"或具体范围
谁能处理         角色名
下一步           一个具名的可点击动作
▸ 技术详情       错误码 · 对象 · request_id · 时间 · 复制诊断
```

`HTTP 404 / QUERY_OBJECT_NOT_FOUND` 只允许出现在折叠的技术详情里。

### 6.3 视觉预算

空态容器 ≤ **200px**，其下必须继续渲染该页其余可用内容。
**空态是一条通知，不是一堵墙。**

## 10. 人类判断的类型系统

### 10.1 A2 的第二种绑定

机器状态绑字段；**人类判断绑一个人**。没有第三种。

原 A2（只允许绑字段）在结构上**禁止**了这个产品显示它唯一真正重要的那句话——
"这个形式陈述忠实于那个中文命题"——因为没有任何字段能承载它。

### 10.2 `AttributedJudgment`

```
AttributedJudgment {
  statement            这个人断言了什么（自然语言）
  by, at               具名身份、时间
  saw[]                他实际看了哪些工件（精确引用）
  scope                断言范围，不得外推
  scope_evidenced_by   变异挑战结果（机器测量，非自陈）
  knowingly_skipped[]  **明知而跳过的**
  independence { credential_distinct, session_distinct,
                 holder_distinct: UNKNOWN, attested_by }
}
```

**`knowingly_skipped[]` 的名字必须诚实到它的定义域。**它曾叫 `not_covered[]`，
那个名字在撒谎：一个人不能枚举他没想到的东西——**如果他知道要填它，
他就已经发现错误了。**这个字段只承载"我知道我跳过了第 5 节数值实验"这一类，
**它不界定风险边界，也不假装界定。**

### 10.3 忠实性变异挑战

签署忠实性前，系统生成形式陈述的变异体，要求复核者逐个判定"这还忠实于合同吗"：
量词变异、**定义域边界变异（`n : ℕ` ↔ `n : ℕ, 1 ≤ n` ↔ `n : ℤ, 1 ≤ n`）**、
假设增删、严格/非严格互换、精确否定翻转、回译变异。

一个心里认为"ℕ 从 1 开始"的复核者会把那个变异体判为"忠实"——**他当场暴露，
而且是机器测出来的，不靠他自陈。**

**成本与 Goodhart 的双重收窄：**
- 按**合同版本**施加，不按每次签署（≤5 个变异体 / 合同版本）
- **不是门禁。**低覆盖不阻断，只显示
- 覆盖率显示为「已测覆盖」，**永不显示为满分或绿色**

> 一个公开的、重复施加的、维度固定的测试，测量的不再是被测能力，而是对该测试的适应。
> 机器不学习那个测试，人会。**同一机制施加在两种对象上，一个是测量，一个会自毁。**
> 随机化实例挡不住对维度的适应，因为维度写在规格里。

**定义域限定条款（与「已测覆盖」同屏、同层级、不可折叠）：**

> 变异挑战只能检验**已经被写下来的东西之间的关系**。忠实性失败的主要形式是
> **某样东西没有被写下来**——原题里一个我们还没想到要形式化的维度。
> 构造一个变异体需要先想到那个维度，而"想到"正是失败的那一步。
> 因此「已测覆盖：定义域 ✓ 量词 ✓ 边界 ✓」**不表示形式化忠实**，
> 只表示在已枚举的六个维度上没有测出不一致。

### 10.4 独立性

**产品不能判定两个署名背后是不是同一个人。**凭据同机签发、同人持有，没有判据。

`holder_distinct` 默认 `UNKNOWN`，**`UNKNOWN` 必须被显示**。
产品可观测的是弱证据，界面必须原样显示为弱证据，**永远不得升级成"独立"**：
「不同凭据 · 同一部署 · 持有者是否相同：未知」。

**单人部署中，最终交付卡与 32px 标题同层级、不可折叠地显示：**

> **本部署中，忠实性审计与整篇复核由同一凭据持有者签署。独立性：未经证实。**

这不是自我否定，是准确。**一个数学家加一群智能体可以做出真数学；
他们做不出的是独立复核。把这两件事分开说，正是这个产品和一个看起来很像的赝品之间的全部区别。**
`docs/roles.md` 已写明「缺失：真实人类签名/身份服务 · 未完成前 fail closed」——
这是仓库里已有的立场，前端不得丢掉它。

### 10.5 署名不得比它所担保的结论小

"最终交付"用 32px 显示，则"忠实性由〈姓名〉于〈日期〉断言，已测覆盖〈…〉，
明知跳过〈…〉，独立性〈…〉"必须**同一视觉层级、同屏、不可折叠**。
不是 11px，不是检查器底部，不是"技术详情"。

### 10.6 复核者视图不得同构于主研究者视图

对忠实性 / 整篇复核 / 匿名找漏洞身份：

```
原题（未经任何分解的原始陈述）
        ↕   ← 这两端是否说的是同一件事？
最终形式陈述 + 完整依赖闭包

主研究者的分解（阶段 / 路线 / 合同分栏）→ 默认折叠，
标注："这是主研究者的分解方式，它本身可能是错的。"
```

- **`StageBar` 在复核身份下不渲染。**复核者不需要知道研究到第几步——知道了只会被锚定
- **第四种复核结论：「质疑分解」。**接受 / 拒绝 / 要求修订三种都在主研究者的框架内；
  第四种指向上一层的分解，路由回 S1/S3，不回给 Claim 作者
- **匿名找漏洞者的隔离是界面要求**（`docs/roles.md` 规定的隔离上下文，界面此前从未兑现）：
  不显示作者、不显示研究历史、不显示阶段、不显示其他 Claim 的通过状态

**对照面板的高亮判据是「是否被人明确核对过」，不是语义等价。**
产品判定覆盖状态，不判定数学内容，因此不会成为一个不具名的复核者。

## 11. 条件性定理与"缺口"的两种含义

> **定理.** 假设 GRH 成立，则对所有正实数 $x$ 和所有整数 $n \ge 1$，$P_n(x) > 0$。

这是一篇完全可发表的论文。"假设 GRH"不是免责声明，**它是主要数学贡献**——
它把缺口精确定位到了一个具名的、所有人都认识的、独立的猜想上。

**2.0 在结构上禁止了这一整类真数学：**`obligations_open ≠ 0` → `ClosureWitness` 失败 →
终态链第一环不满足 → "最终交付"永不出现 → 归入 `UNRESOLVED`，
而词典给 `UNRESOLVED` 的解释是"**没做完**"。

**修正：**

1. `outcome` 增加 **`PROVED_CONDITIONAL`**（在显式前提下已证）
2. 合同增加**第六行：显式外部前提**。原五行（对象、定义域、量词、边界、精确否定）
   假设了每一项研究都是绝对的、无前提的
3. obligation 增加 kind **`ACCEPTED_HYPOTHESIS`**：不计入 `obligations_open`，
   由人**署名接受**，生成一条 `AttributedJudgment`
4. 终态链允许在**所有 open obligation 都被显式接受**时闭合，
   且"最终交付"必须与结论同层级列出全部被接受的前提

**这一修正的代价，必须写明：**

"GRH 可接受"与"我那条证不出的引理可接受"，区别是**纯数学判断**，没有任何字段能表达。
GRH 可接受是因为一百五十年没人证伪它、有大量独立证据、整个学科接受它。
**没有服务端能判定这件事。**

于是 `closure_readiness.closure_witness`——终态链的第一环，此前被当作纯机器可判的那一环——
**变成了一个 `AttributedJudgment`**。按 A8，它不能再放进 `publishable.machine`。

**因此，如实记录 `publishable.machine` 那一栏里剩下的东西：**

> **只剩「Lean 退出码为 0」和「PDF 编译成功」。**

而这两件事，正是这个产品从第一页起就在警告用户不要与数学正确性混淆的那两件事。
**这不是一个需要被修补的结论，这是这个产品最诚实的一句话，它必须出现在界面上：**
`publishable` 两栏并列时，machine 栏的标题固定为
**「机器可判定的部分（不含数学正确性）」**。

## 12. 决策历史：过去不是可选项

**成品定理可以重建，失败的尝试和放弃的理由不可重建。**

**(1) 放弃是写操作，写操作必须有理由。**`DecisionRecord`：任何放弃、停止路线、拒绝、
降级、改分解都必须携带「为什么」——系统做的填 `considered[].why_rejected`，
人做的生成 `AttributedJudgment`。**没有理由不允许提交。**

**(2) 瞬时投影字段降为事件负载。**`considered[]`、`next_action.why`、
`ThinnestLinkPanel` 的历次内容、`NO_SUGGESTION.scope`、历次 `ResearcherBelief`
进 append-only 事件账，新投影 `DecisionHistory` 读它们。

**(3) 过去是每个对象的一维，不是一个首屏挂件。**每个检查器加**「历程」**标签页，
**与当前状态平级**（不进技术详情）：经历过几版、被谁质疑过、为什么被放弃、谁复活了它。

**(4) 分解的理由必须可见。**合同记录的是分解的**结果**；「质疑分解」这个动作
要求当初的**理由**存在，否则那个按钮按不下去。

## 13. 实时、断线与对账

- **连接状态**只在顶栏 `ConnectionChip`：已连接 / 补齐中 / 已断开，展开看 revision、cursor、
  最后事件时间。cursor 跳号不显示为异常
- **补齐中**：不阻塞界面，不弹模态；已加载内容保持可读
- **`CURSOR_EXPIRED`**：「研究状态已更新较多，需要重新读取」+ 一个按钮
- **写操作回执**：`PENDING` 期间主动作变"处理中"且**不显示成功**；
  `OUTCOME_UNKNOWN` 提供四个受管动作（查上游 / 导入回执 / 新建重试 / 保持阻塞），
  **绝不自动重试**
- **陈旧 revision**：「你看到的是修订 r3，当前是 r5」+ 差异摘要 + "重新应用我的草稿"

## 14. 可访问性

- **对比度** ≥ 4.5:1（正文与控件）/ 3:1（大字与图形边界），CI 跑令牌组合校验
- **不靠颜色**：每个状态色配形状符号 + 文字标签
- **键盘**：全流程可键盘完成；焦点环 2px 高对比；跳转链接
- **焦点管理**：实时事件到达不移动焦点；动作完成后焦点落到结果区首个可交互元素
- **缩放**：200% 不横向滚动，400% 保留查看/搜索/审查/恢复
- **图的等价**：每个图有列表/树表视图，共享选择与筛选
- **公式**：`aria-label` + 复制 LaTeX
- **动效**：尊重 `prefers-reduced-motion`；实时更新节流 ≥ 500ms
- **屏幕阅读器**：状态变化 `aria-live="polite"`，错误 `assertive`，不播报 cursor 与心跳

**验收不接受纯自动扫描**：必须由仅键盘用户与屏幕阅读器用户实际走完全流程（1.1 F16）。

## 15. 性能、成本与感知

### 15.1 机器侧

- 首屏骨架 < 300ms；**阶段条与主动作是第一批渲染的内容**
- `StageProjection` 不做图遍历；闭包走 `ImpactProjection`，有独立的加载/陈旧/失败三态
- 局部事实图默认 ≤ 200 节点，Graphviz WASM 布局 < 1s，相同输入布局稳定
- `ObjectPicker` 在 3000 条下 p95 ≤ 300ms
- 大列表虚拟滚动（≥ 500 历史项）
- **禁止骨架屏冒充数据**；**禁止乐观 UI**（`DECIDED` 之前不改变任何数学状态显示）

### 15.2 人力成本是一等指标

**这个产品的每一条诚实性设计，成本都落在同一个人身上**：不自动重试 → 他手动；
不乐观 UI → 他等；变异挑战 → 他判；署名 → 他担责。**这份账单此前从未被开出来。**

必须测量并公布：

- 用本系统完成一条引理，相对本地裸 Lean 的**额外人时**
- 单次"提交待核验命题"的交互次数（目标 ≤ 3）
- 已知标识符定位到对象的交互次数（目标 ≤ 2）
- 一次忠实性签署的判定次数与耗时

**这不是"越低越好"的空话，是要被写下来、被看见、被用来砍流程的数字。**

### 15.3 绕过不被惩罚，被欢迎

用户在本地 VS Code 里跑 Lean、在纸上算、和合作者吵完再回来录入，产品看不见任何一步。
**惩罚导入等于奖励隐瞒**——你无法惩罚一个观测不到的行为，只能惩罚**承认**了它的人。

因此：
- `IMPORT_VERIFICATION` 是**一等路径**，低摩擦
- 证据等级只反映**证据本身是什么**（纸面推导 vs Lean 证明），**不反映在哪里做的**
- **补录是真功能**：事后录入的内容带**两个时间戳**（真实发生时间 / 录入时间），
  标注"事后录入"。这让边界朝诚实的方向可渗透

## 17. 验收与门禁

### 17.1 三套人工验收

**17.1a 首次用户**（不看文档的数学研究人员）：登录并选择研究 → **不滚动**说出当前阶段与
下一步 → 查看合同与材料 → 找到并启动一条路线 → 从列表选择 Claim 查看证据与谱系 →

**17.1b 第 30 天用户**：单次提交 ≤ 3 次交互；40 条/天会话中无强制模态；
已知标识符定位 ≤ 2 次交互；`ObjectPicker` 在 3000 条下可用。

**17.1c 边界**：`OUTCOME_UNKNOWN` 四个受管动作各走一遍、Matlas 504、缺包、
外部标识符导入、`CURSOR_EXPIRED`、补录。

**三套同等阻断力。**17.1a 与 17.1c 之间的缝隙曾是这份 PRD 最需要人正确操作、
却谁都没验收的地方。

## 18. 交付顺序、未解决依赖、以及被删掉的东西

### 18.1 未解决依赖（2.1 无法独立交付）

**A8 需要 `EvidenceComposition`，它不在 1.1 §8 的后端能力清单里。**

```
EvidenceComposition（每条 Fact / 每条边携带，沿依赖闭包传播）
  machine_core        机器可判定的部分
  human_asserted[]    人类断言依赖（含署名、时间、已测覆盖）
  soft_deps[]         SOFT 支撑
  external_deps[]     外部世界依赖（mathlib、上游服务）
```

传播语义与 Lean 的 `#print axioms` / `sorry` 污染同构，已知可做，**但它是后端能力**。
**异质性是这个产品的基底，不是几个 bug**：`Fact` 的成立是 Lean ∧ 忠实 ∧ 前提有效；
`ClosureWitness` 的缺口判定含忠实性；`EvidenceGradeChip` 六档混了运维事实与人的评级。
**在 `EvidenceComposition` 落地前，A8 只能被逐点执行，不能被系统性保证。**
本文要求修改 1.1 §8。

### 18.2 交付顺序

每一批的完成定义包含一次**具名的、阻断性的「数学家攻击」**——**攻击，不是验收**：

```
验收问："能不能完成任务"      → 通过 / 不通过
攻击问："我用它第三天会不会崩"  → 输出"我最不能接受的一条"

· 攻击者必须是**未参与该批次设计**的数学研究者
· 产出必须导致本批次的规格变更，或一条书面的、具名的不变更理由
· 无攻击记录 → 不得进入下一批（与 G1–G15 同级阻断）
· "我最不能接受的一条"逐批归档，成为该批次证据的一部分
```

| 批 | 内容 | 攻击/验收 |
|---|---|---|
| 1 | `StageProjection`（含 `stages[]`、`NO_SUGGESTION`/`NOT_COMPUTED`）+ `StageBar` + `NextActionCard` + `ResearcherBelief` + **`lexicon.json`（数学侧署名）** + G1–G4 | **第一次数学家攻击** |
| 2 | 文本管线 + G8；03/05/11 互斥状态清理；错误四段式；回执语义 | 攻击 + **17.1c** |
| 3 | 七类空态 + `DisabledReason` + G6/G12 | 攻击 |
| 4 | 首屏预算重构 + `ThinnestLinkPanel` + 回归者简报 + G11 | 攻击 + **17.1a** |
| 5 | `ObjectPicker` + `ImpactPreview` + `ReceiptStrip` + 命令面板 + G5 | 攻击 + **17.1b** |
| 6 | `AttributedJudgment` + 变异挑战 + `independence` + 复核者去同构 + `PROVED_CONDITIONAL` + G14/G15 | 攻击 |
| 7 | `DecisionRecord` + `DecisionHistory` + 「历程」+ 补录 + A9 | 攻击 |
| 8 | 可访问性、规模、逐页收敛 + G9/G10 + 三套验收**回归** | 攻击 |

**批次 1 交付后立即有一名真实数学家坐下来攻击。**批次 1 交的正是审计里失败得最惨的东西
（顶栏 RUNNING / 合同页尚未创建 / 路线页 EMPTY / 卷宗页已冻结），它一交付就可以被问
"告诉我现在到哪了、下一步是什么"。

**"每批次都不是可停止的 MVP"修正为：不是可发布的 MVP，但必须是可被攻击的。**

### 18.3 被删掉的东西

五轮攻防里删掉的 8 样全是谎言（`index/total`、`preserved_count`、`EMPTY` 一词、
"完成 43%"、常驻 cursor 条、56px 大标题、`PAUSE RESEARCH` 主动作位、
"绑错在类型层面被消除"这句话），加上了约 30 样。**一个只有加号的回路不会收敛。**

**因此从产品范围中删除以下四项，让这个产品做得更少：**

1. **消融视图与远域机会视图**（原 03 二级）。它们是**研究计划的仪器**，
   用来支撑 RK 项目自己关于远域迁移的论证，**不是研究者做数学的工具**。
   移到离线分析笔记本，不进产品前端。
2. **题池与科研谱系 / 批量研究**（原 01 二级）。批量 arXiv 题池管理是**另一个产品**
   （研究计划管理），被螺在了一个单研究工作台上。删除。
3. **管理中心的图形化备份 / 恢复 / 升级 / 迁移 / 诊断包**。单机部署上这些是 CLI 任务，
   为它们做 GUI 是 §16.10 里最大的一块，而**没有任何数学家会碰它**。
   保留只读健康页；其余回 CLI。
4. **双表面视觉系统**（原 §8.1）。维护两套色板、两套对比度矩阵、两套组件皮肤，
   换不来任何用户价值，而"跳到了另一个软件"的观感正是它造成的。收敛为单表面 + 加深层。

**判据：我是用它做研究的人，我不需要它完整，我需要它在第三天还活着。**

## 19. 攻防记录与本文的方法论结论

本文 2.0 → 2.1 的全部修订，来自与一位在职研究数学家的五轮苏格拉底式攻防（2026-08-15）。

**逐轮最不能接受的一条：**

1. `next_action.kind` 的枚举里没有"不知道"，而门禁强制它非空——**规格要求系统在它不知道的时候也说话。**
2. `preserved_count` 与 `publishable` 是同一个错误的两次犯案：**把机器算的和人说的求和成一个标量，然后认真地保证界面绑对了那个标量。**
3. **这个产品最有效的质量机制是"一个数学家坐在这里骂它"，而它被排在了第八批。**
4. 终态链第七环叫"独立"，它决定前六环加起来是不是数学，**而它在类型系统里连一个字段都没有。**
5. A1 断言存在一个知道"这项研究现在到哪一步"的服务端。**知道那件事的人是研究者，而他在产品里连一个字段都没有。**

**方法论结论（这是本文最重要的一条，它决定了 §18.2 的结构）：**

> 这十几处修订**没有一处是从原则推导出来的，全部来自那位数学家说的话**。
> 上一版失败的判定是"能力在，人用不了"，而它之所以发生，是因为
> **从规格到实装的整条链上，没有任何一个时刻有人坐下来看着屏幕说"这不能用"**，
> 直到全部实装完成之后的独立审计。
>
> 因此「数学家攻击」不是质量保证环节，**它是设计方法本身**。
> 把它写成每批的阻断条件（§18.2），是本文唯一能防止 2.1 重蹈 1.1 覆辙的机制。

## 20. 发布口径与非目标

**发布口径**：17.1a/b/c 与 G1–G15 全部通过前，只能写"可视化产品开发中"。
不得写"完整数学研究工作台"、"实时 DAG 已完成"、"动态 Worker 已支持"。
Rethlas 等外部能力只在当前部署真实健康并取得当前 run 回执时显示可用。

**非目标：**
- 多租户 SaaS 的组织/计费界面
- 聊天主视图；用模型头像数量表达研究进展
- 移动端大图编辑（窄屏只保证查看、搜索、指导、审查、恢复）
- 乐观 UI 与进度条动画
- 主页或普通导航中的候选论文预览
- 用漂亮的图、置信度或工具退出码替代**数学验证**（注意：这禁止的是把置信度喂给数学判定，
  **不禁止界面里有人表达自己的信念**——见 §3.5）
- 消融 / 题池 / 图形化运维 / 双表面（§18.3）
